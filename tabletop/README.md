# Пути Раскола — единый эталон и сборка для двух платформ

Один запуск собирает мод Tabletop Simulator (TTS) и импортируемый архив PlayingCards.io из одинаковых данных. Текущий комплект: поле 7×5, две колоды по 88 карт, две базы и 12 барьеров.

Текущая версия эталона — v15. Книжка правил содержит 8 страниц; при добавлении терминов и пояснений генератор создаёт продолжения автоматически.

## Расположение в общем проекте

Этот проект находится в `tabletop/` репозитория `Navimar/shardfront`, рядом с Godot-игрой. Рабочая папка на этом Mac — `/Users/igor/Godot/shardfront/tabletop`. Все команды ниже выполняются из неё:

```bash
cd /Users/igor/Godot/shardfront/tabletop
```

Из корня `shardfront` сборку также можно запустить командой `python3 tabletop/scripts/build_game.py`: пути по умолчанию вычисляются относительно скриптов.

Исходники, тесты, документация и исторические материалы в `mod/` хранятся в основном Git. Папки `output/`, `tmp/`, виртуальные окружения и Python-кеши исключены из него. Локальная копия отдельного репозитория `Navimar/putiraskola-assets` сохранена в `output/github-pages/`; она не является подмодулем основного репозитория. Файл `.gdignore` исключает весь `tabletop/` из импорта Godot.

В старой папке `/Users/igor/Developer/PRIVATE/putiraskola` оставлен только README с указанием нового расположения. Файлы проекта хранятся в `tabletop/`. Для дальнейшей работы в Codex открывайте `/Users/igor/Godot/shardfront`. Перенос не требует повторной публикации модуля TTS или его HTTPS-ассетов.

## Где редактировать игру

- `source/game/game.json` — все карты, сила, тексты, значки, состав колод, базы, барьеры и ссылки на изображения;
- `source/game/rules.md` — полный текст правил;
- `source/game/assets/` — исходные изображения;
- `source/templates/` — оформление и расположение объектов платформ, без независимого каталога существ.

Подробнее о добавлении карт и числе копий — в `source/game/README.md`. Все изменения игры вносите в эталон. `source/pcio/`, `source/extra_cards.json` и прежние файлы в `mod/` сохранены для истории и проверки миграции.

## Сборка одной командой

```bash
python3 scripts/build_game.py
```

На этом Mac используется установленный Python либо готовый Python из Codex, если в системном окружении отсутствуют зависимости. Для самостоятельного окружения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/build_game.py
```

Рендер карточек использует Arial и Apple Color Emoji из macOS. Текущие сцены поддерживают поле 7×5 и 12 барьеров; другой размер требует обновления шаблонов и схем правил. Число типов карт и число копий в колодах задаются эталоном, разбиение на атласы рассчитывается автоматически.

## Результаты

- `output/build/tts/puti_raskola.json` — готовое сохранение TTS, основанное на проверенной сцене, сериализованной TTS;
- `output/build/tts/assets/` — карточные атласы, поле, рубашки, базы, барьеры и PDF правил;
- `output/build/tts/tts_bootstrap.lua` — сброс партии, восстанавливающий тот же состав колод и тексты карт;
- `output/build/tts/rules.pdf` — иллюстрированная книжка правил;
- `output/build/pcio/puti_raskola.pcio` — самодостаточный архив для импорта в PlayingCards.io, включая Подрывника, без страниц правил;
- `output/build/pcio/widgets.json` и `userassets/` — распакованная версия архива для проверки;
- `output/build/build-report.json` — результат проверки и SHA-256 исходников и всех созданных файлов.

По умолчанию TTS ссылается на локальные файлы внутри результата сборки. Этот вариант предназначен для локальной игры: для сетевой партии нужны опубликованные HTTPS-изображения. Архив PlayingCards.io уже содержит все используемые изображения.

Для PlayingCards.io сборка автоматически уменьшает иллюстрации существ до 1024 пикселей по длинной стороне и сохраняет их как JPEG с качеством 85. Маленькие изображения не увеличиваются; прозрачность сводится на белый фон. Обе колоды используют общие изображения. Оригиналы в эталоне сохраняют своё качество. Правила включаются только в TTS.

Для TTS карточные атласы сохраняются как JPEG с качеством 90 без уменьшения разрешения. Цветовая детализация сохраняется (`subsampling=0`), чтобы текст и значки оставались чёткими.

## Проверка

Сборка завершается успешно только после сравнения обеих платформ с эталоном: названия, сила, значки, способности, число копий, изображения, правила, целостность архива, уникальность идентификаторов и колоды после сброса TTS. Проверить существующий результат повторно:

```bash
python3 scripts/validate_build.py
```

Изменённый эталон или повреждённый результат обнаруживаются по данным и контрольным суммам. Автоматические проверки кода:

```bash
python3 -m unittest discover -s tests -v
```

При установленном Lua 5.2 сценарии выбора места проверяются командой `lua tests/test_seat_choice.lua`: загрузка, подключение, занятые места, одновременный выбор, отмена и переподключение.

## Импорт

**PlayingCards.io:** откройте [страницу импорта](https://playingcards.io/import) и выберите `output/build/pcio/puti_raskola.pcio`. В существующей комнате импорт доступен в Edit Mode → Room Options → Import. Порядок импорта описан в [официальной инструкции](https://playingcards.io/docs/room-import-export).

**TTS:** загрузите `output/build/tts/puti_raskola.json` как сохранение. Папку `output/build/tts/assets/` оставьте на месте: локальные ссылки содержат абсолютные пути.

После загрузки и при подключении нового игрока мод предлагает выбрать свободное синее или красное место. Для игроков, уже занявших одно из этих мест, окно не появляется. Выбор можно отменить, чтобы остаться наблюдателем.

Карты на поле размещаются свободно: привязка к клеткам и автоматическая раскладка стопок отключены. Точки привязки остаются только для колод, сброса и барьеров вне поля.

При загрузке и появлении карт и колод мод включает Auto Raise и отключает Sticky: переносимые карты поднимаются над другими объектами, а карты сверху не тянутся за нижней. Эти настройки сохраняются при сбросе партии.

Для установки в локальный список Workshop можно использовать:

```bash
python3 scripts/install_macos.py --source output/build/tts/puti_raskola.json
```

Установка — отдельная команда; сборка не изменяет установленную игру и не публикует файлы.

## Публикация ресурсов и установка сетевой версии TTS

Соберите и проверьте игру, опубликуйте её ресурсы на GitHub Pages и установите сохранение с полученными HTTPS-ссылками:

```bash
python3 scripts/build_game.py --publish
python3 scripts/install_macos.py --source output/build/tts/puti_raskola.json
```

Публикация использует публичный репозиторий Navimar/putiraskola-assets и GitHub Pages. Нужны git и GitHub CLI с действующим входом (gh auth login). Загружаются только ресурсы, перечисленные в манифесте сборки, и готовое сохранение TTS. Адрес каждого ресурса содержит SHA-256: изменённая картинка получает новую ссылку, а старые файлы сохраняются для прежних модулей. После успешного деплоя все файлы скачиваются и проверяются по контрольным суммам; только затем обновляются output/public_assets.json, ссылки сохранения и колод после сброса. Повторный рендер после публикации не нужен. Готовое сохранение доступно на https://navimar.github.io/putiraskola-assets/. Параметр --repository OWNER/NAME позволяет выбрать другой репозиторий, локальная копия файлов публикации хранится в output/github-pages/. Установка обновляет локальную запись Workshop; публикация в каталоге Steam Workshop этой командой не выполняется. Архив PlayingCards.io импортируется отдельно в нужную комнату.

## Дополнительные параметры

```bash
python3 scripts/build_game.py --game source/game/game.json --output output/build
python3 scripts/build_game.py --public-assets path/to/public_assets.json
```

`--public-assets` использует уже опубликованные изображения только при полном совпадении контрольных сумм с новой сборкой. Устаревшие ссылки приводят к ошибке. Параметр ничего не загружает на серверы.

Старые утилиты в `scripts/` для публикации, отладки сцены и миграции сохранений TTS оставлены для совместимости. Основной путь сборки теперь — `build_game.py`.
